知识底座

笔记、对话、代码仓库里的资料最终都要能被找到、被引用、被复用。Hetu 用四层能力做这件事：知识库（向量索引）、知识图谱（实体关系）、Wiki（成篇文档）、记忆（长期偏好与事实）。

知识库：把资料变成可检索的块

  • 三种来源：笔记、上传文件（文档 / 文本等）、网址（网页正文抓取）。
  • 分块与向量：内容按结构分块后调用 Embedding 模型生成向量，SQLite 用 sqlite-vec，PostgreSQL 用 pgvector。
  • 三个页签：概览（覆盖率、维度、索引项数）、索引管理（逐项状态、分块数、重新索引、批量补索引）、搜索测试（可调 Top-K，命中片段高亮）。
  • 轮询只在有事发生时：存在未索引项或运行中任务时页面才自动刷新。

向量维度必须与 Embedding 模型一致（配置项 Embedding:Dimensions，默认 1536）。维度不匹配时 SQLite 会直接写入失败。

知识图谱：把资料变成关系

  • 从任意笔记一键抽取实体与关系，抽取结果做去重合并；后台任务里能看到每次抽取的耗时。
  • 实体类型：概念、人物、组织、技术、项目、自定义；关系类型：属于、相关、依赖、包含、对比、自定义。
  • 力导向布局，支持缩放 / 平移 / 搜索 / 重置；点实体可看关联笔记并跳回编辑器。

Wiki：把项目资料变成成篇文档

  • 在「项目」或「Wiki」页对某个仓库发起生成：AI 依据项目资料（README、目录结构、代码片段，可叠加语义检索）生成模块页 + 项目总览。
  • 结果按套件分组（一次生成 = 一套），标注生成时间、页数与「有更新」提示。
  • 生成过程是后台任务，可在「后台任务」页看阶段、进度、耗时与失败原因。

记忆与 Dream：跨会话的长期上下文

  • 记忆条目含内容、类别（偏好 / 身份 / 工作 / 习惯 / 知识…）与重要性（星级），支持搜索与作用域筛选。
  • 作用域：全局 / 会话 / 项目——对话时按当前上下文注入，不会把项目细节带到无关话题里。
  • 记忆图：可视化记忆之间的关联。
  • Dream 巩固：按「衰退天数 / 遗忘天数」定期合并重复、衰减过时、遗忘无用记忆，可在页面上手动跑一次。
  • 对话里通过输入框的「记忆」开关触发召回，也可以让模型用 search_memory 工具主动查。

怎么用起来最顺

场景建议动作
刚导入一批资料知识库 → 索引管理 → 批量生成索引，等任务跑完再看覆盖率
想确认检索质量知识库 → 搜索测试，换几个问法看命中片段
一篇笔记写长了笔记顶部「提取图谱」+「添加标签」，之后能在图谱里按概念找回来
接手一个陌生仓库项目 → 生成 Wiki，再在 Code 会话里追问细节
希望 AI 记住你的偏好在对话里明确说一次，或手动到「记忆」页新增一条全局记忆
