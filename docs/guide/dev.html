参与开发

Hetu 是一个 ASP.NET Core + React 的全栈项目，外加一个 Tauri 桌面壳。欢迎提 Issue 与 PR；动手前先读仓库根目录的 AGENTS.md。

架构与目录

Hetu/
├── src/
│   ├── Hetu.Api/                                 # 控制器、SSE 流、后台 Worker
│   ├── Hetu.Core/                                # 实体、服务、仓储接口（不依赖 EF/ASP.NET 实现）
│   ├── Hetu.Infrastructure/                       # EF Core、仓储实现、AI Provider、MCP、sqlite-vec
│   ├── Hetu.Infrastructure.PostgresMigrations/    # PostgreSQL 迁移
│   └── Hetu.Shared/                               # DTO / 枚举 / 常量（前后端契约）
├── frontend/                                      # React + Vite
├── shell/hetu-desktop/                            # Tauri 2 外壳（Rust + 安装器钩子）
├── scripts/                                       # 启动 / 打包 / 发版 / 冒烟测试
└── docs/                                          # 本网站与截图

依赖方向是 Api → Core ← Infrastructure：Core 只放领域模型、服务与接口，具体实现（数据库、AI、进程、文件系统）放 Infrastructure。

构建与验证

# 后端（期望 0 告警 0 错误）
dotnet build src/Hetu.Api/Hetu.Api.csproj -c Release -v q

# 前端静态检查与类型检查
cd frontend && npx eslint . && npx tsc -b

# API 冒烟（后端已启动）
./scripts/test-api.sh
告警零容忍：不接受 #pragma warning disable、SuppressMessage、eslint-disable、@ts-ignore 这类抑制；可空性就加判空，平台 API 就加 OperatingSystem.IsXxx 守卫，依赖漏洞就升级包。

几条容易踩的约定

主题约定
列表接口必须分页，且分页与排序在数据库完成（不要 ToList() 后再 Skip/Take）
SQLite 时间排序provider 不支持在 SQL 中排序/聚合 DateTimeOffset，用 GetPagedByDateAsync / CountByAsync / PruneAsync，或投影后在内存定序
前端副作用不要在 useEffect 里同步 setState；用派生值表达「跟随 prop 变化」
组件导出组件文件只导出组件，工具函数放 utils/（否则 Fast Refresh 失效）
文案中英文两份必须同步新增（Locales/{zh,en} 与 i18n/locales/{zh,en}）
异步迭代器带取消令牌的参数必须标 [EnumeratorCancellation]
长任务交给 IBackgroundTaskCoordinator（前端「后台任务」可见），别用即发即忘的 Task.Run

发版流程

  1. 同步两处版本号：shell/hetu-desktop/src-tauri/tauri.conf.json 与 src/Hetu.Api/Hetu.Api.csproj（前端「关于」页读的是后者）。
  2. 提 PR 合并到 main。
  3. 打 tag 触发 CI：
pwsh ./scripts/tag-release.ps1 -Version 0.4.0

CI 会构建 fat / slim 两个渠道的 Windows 与 Linux 安装包（带签名）、生成更新清单（latest*.json 主源与三个镜像），并创建 GitHub Release。任一渠道清单生成失败会让发布直接失败——避免发出「更新点不动」的版本。
