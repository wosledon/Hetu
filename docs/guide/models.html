模型与用量

Hetu 自己不提供模型，只做「协议适配 + 场景编排」：你填供应商与 Key，它负责把合适的能力分配到合适的场景，并记下每一次调用的用量。

供应商与模型

  1. 左侧「大模型」→ 新增供应商，选择协议：OpenAI 兼容（绝大多数自建/中转服务）或 Anthropic，填 Base URL 与 API Key。
  2. 在该供应商下新增模型，用途三类：
    • chat：对话、Code 会话、Agent 循环
    • embedding：知识库向量化、语义检索
    • completion：轻量补全 / 改写类调用
  3. 同一用途可以有多个模型，随时在输入工具带里临时换。
API Key 用 ASP.NET DataProtection 加密后落库（Windows 上走 DPAPI），不会以明文出现在数据库、日志或接口响应里。
Anthropic 没有公开的 Embedding 接口，embedding 用途请选 OpenAI 兼容供应商。

按场景指定默认模型

设置 → 默认模型，可以分别指定：对话、编码会话、Wiki 生成、知识图谱抽取、话题整理、笔记 AI、查询改写等。原则是：贵的模型留给需要推理的场景，索引与整理用便宜快的。

代理服务：把 Hetu 的模型能力接给别的工具

「代理服务」页把已配置的模型暴露成 OpenAI 兼容与 Anthropic 兼容的本地接口，于是编辑器、CLI、脚本都能指向 Hetu 使用同一批 Key 与同一份用量统计：

# 以 OpenAI 兼容客户端为例，把 Base URL 指到本机
# Base URL: http://localhost:5000/api/proxy/openai/v1
# API Key : 在「代理服务」页面生成的本地 Key

curl http://localhost:5000/api/proxy/openai/v1/models

代理页可以配置路由（哪个模型对外可见）、影子模型（同一请求额外打给另一个模型做对比）等策略。

用量与成本

  • 概览：总消息数、Token 总量、输入 / 压缩后 / 输出 / 缓存 Token、平均延迟、活跃天数、今日用量。
  • 趋势：近 7 / 30 / 90 天曲线；周×时、年×日两张热力图。
  • 分布：按模型、按来源（对话 / 编码会话 / 看板 / Wiki / 图谱 / 定时任务 / 代理…）拆分。
  • 明细：分页的请求日志，可按来源与业务引用（话题 / 会话 / 任务）过滤，含内容摘要与延迟。

上下文压缩管道

长会话不可能无限塞进上下文，设置 → 成本控制 里配置压缩策略：什么时候压缩、压缩到多长、用哪个模型做摘要。压缩后实际发送的 Token（CompressedTokens）会与原始输入一起记入用量，省了多少一目了然。

省 Token 的几个实践

做法效果
把 索引 / 整理 / 打标签 指到便宜的小模型这些任务量大但不需要强推理
只在需要时打开「知识库」「记忆」开关避免每次请求都注入检索结果
Code 会话用独立工作树 + 明确任务边界减少来回试错轮次
长任务用 Autopilot，短问答用交互式前者省确认轮次，后者省无用工具调用
