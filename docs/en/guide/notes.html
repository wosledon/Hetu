Notes

Entry point: Notes in the left navigation (route /). Three columns: nested notes tree, note list, editor.

Editor

ItemDetails
LayoutTitle, metadata and body share one centered reading column (~48rem) instead of stretching across wide screens; when the note has headings a table of contents appears to the left of the column — click to jump, the current section highlights while scrolling, and it hides itself when space runs out (e.g. split view)
ModesWYSIWYG (Milkdown: headings, lists, tables, code blocks, KaTeX math, Mermaid diagrams, images, task lists) and source mode (CodeMirror with Markdown highlighting); split view supported
AutosaveSaves ~3 seconds after you stop typing; the header shows draft / saved state; Ctrl+S saves immediately
ImagesPaste or drop to upload into the attachments directory and insert a reference
RenderingMermaid, KaTeX, GFM tables and task lists; output is sanitized with DOMPurify

AI writing

  • Selection actions: select text to polish, translate, condense, expand, explain or run a custom prompt; replace the selection or insert below.
  • Note assistant: a whole-note chat panel with per-call model selection, for requests like “rewrite this section as bullets”.
  • In-note actions: buttons in the editor toolbar — generate knowledge-base index, extract knowledge graph, generate tags, generate a flowchart (Mermaid block). Each runs as a background task and writes results back.

Nested notes and tags

FeatureBehaviour
Nested notesUnlimited nesting: any note can hold child notes — create a sub-note from the row''s plus button or context menu, rename by double-clicking, drag into place via the “Move to root” action; deleting a parent moves the whole subtree to the trash
Note iconsEvery note shows a unified note icon; click it to pick an emoji (searchable), or reset to the default
TagsManaged on the Tags page (/tags): colors, rename, merge; the note list can filter by tag
Pin / favoritePinned notes sort first, then by last update — ordering happens in the database so paging stays stable
SearchSearch box above the list matches title and content

Version history

  • A snapshot is written on every content change; the most recent 20 versions per note are kept (older rows are removed with a single SQL DELETE).
  • Preview any version, compare, and restore in one click — restoring first snapshots the current content as a new version.

Share links

  • Create a public read-only link per note: permanent, 24 hours or 3 days.
  • View counts are recorded and links can be revoked; the public route is /share/:code and only renders that note.

Trash and export

  • Trash (/trash): restore or permanently delete; items are purged after 30 days by default.
  • Export: Settings → Data & backup exports all notes as a Markdown archive and can back up or restore the database file. See Data & security.
