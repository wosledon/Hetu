Extensions & MCP

Four systems decide what the agent can do, under which persona, and which external tools it can reach.

Agents (prompt presets)

Entry: /agents. An agent = system prompt + model preference + tool allowlist + per-tool approval policy.

ItemDetails
Categories and searchGroup by purpose (coding, writing, analysis …) and search by name
Tool allowlistRestrict which tools the agent may call
Approval policyPer tool: silent / auto / ask
Import / exportJSON import and export of all agents for backup or sharing

Skills

Entry: /skills. A skill is a reusable prompt template, invoked in chat with /skill-name.

SourceDetails
Built-inTranslate, summarize, explain, polish — available immediately
CustomYour own prompt template and system prompt; test output right on the page
On-disk directoriesLoad Markdown / JSON skill files from configured directories — good for sharing via a repository

Tools

Entry: /tools. Built-in tools can be toggled; disabled tools are not callable.

ToolPurpose
Note search / read / create / updateRead and write notes from chat, with conditional search
Web searchFetch external information
Memory search / createQuery and write long-term memory
Graph searchQuery entities and relations
Todo listEmit a structured plan and check items off live
Command executionRun commands in the project workspace (permission-mode governed)
File operationsList, read, write, move, delete
Ask questionInteractive question when a decision is needed

MCP servers

Entry: Settings → MCP server. Connect external Model Context Protocol services to bring their tools into chat.

ItemDetails
Transportstdio: spawns a child process and speaks JSON-RPC 2.0 (fully supported). sse: configurable, not wired up yet
Connection configJSON — command / args / env for stdio, or url for sse
Tool discoveryCalls tools/list and merges discovered tools into the chat toolbelt
Tool invocationCalls tools/call; arguments and results render structurally in the message stream
Enable / disablePer server, with ordering
MCP tools share the same permission modes and approval policies as built-in tools; run a new server in “ask” mode first if you are unsure what it does.

Configuration examples

MCP server (stdio)

{
  "command": "npx",
  "args": ["-y", "@modelcontextprotocol/server-filesystem", "E:\\repos"],
  "env": { "NODE_ENV": "production" }
}

Skill file (on-disk directory)

---
name: code-review
description: Review changes against a fixed checklist
---
Review the selected code in this order:
1. Correctness and edge cases
2. Resource cleanup and concurrency
3. Naming and readability
4. Consistency with the surrounding module

Configure the skill directories in settings; a file with the same name as a database skill wins.

Agent (import / export JSON)

{
  "name": "Code reviewer",
  "category": "coding",
  "systemPrompt": "Report only real defects, each with a minimal reproduction and a fix.",
  "allowedTools": ["read_file", "search_code", "run_command"],
  "toolPolicies": { "run_command": "ask", "update_note": "silent" }
}

Apps (embedded browser)

Entry: /apps. Register frequently used pages as “apps” and open them inside the app instead of switching windows.

ItemDetails
RegistrationName plus URL (a local service such as http://localhost:5174, or any site)
OpeningEmbedded view with address bar, back / forward, reload and quick links
Timeout hintWhen a site refuses embedding via X-Frame-Options / CSP, a hint appears after 4 seconds suggesting the system browser
