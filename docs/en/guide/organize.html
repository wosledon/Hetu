Kanban & automation

Work items with tracking: the Kanban board, workflows, background and cron jobs, and the inbox.

Kanban board

Entry: Kanban (/kanban), detail view at /kanban/:taskId.

ColumnMeaning
In progressPicked up by an agent and running
ReviewAgent finished; waiting for your confirmation
BlockedMissing information or failed execution, needs a human
DoneConfirmed complete
ArchivedHistory (filterable by time range)
Task fieldDetails
Title / descriptionWhat to do; the more concrete the description, the more reliable the run
Assigned agentApplies a prompt preset (possibly with its own tool allowlist and approvals)
Priority / categoryUsed for board filtering and ordering
Run stepsPer execution: each action, duration and output summary
CommentsHuman–agent thread; the agent reads it while executing

Execution obeys the same permission modes and task system: a run creates a KanbanTaskExecute background task, and failures show their reason in the task detail.

Workflows

Entry: /workflows. Draw multi-step agent tasks as a flow — handy for repeatable sequences like “research → implement → self-test”.

ItemDetails
NodesEach node is an agent task with its own prompt, agent and dependencies
Enable / disableWhole workflows can be toggled so drafts stay around
RunsEvery run records node status, duration and artifacts, viewable as history

Background tasks

Entry: /tasks/background. Every long-running operation is queued here with status, duration and failure reason.

Task typeTriggered by
Generate embeddingNote indexing, batch index
Generate knowledge item embeddingFile / URL indexing
Graph extract“Extract graph” on a note
Wiki generateProject page / Wiki page
Kanban task executeAssigning an agent on the board
Workflow runWorkflow execution

States: queued / running / completed / failed; filter by type, clear completed items, delete individually. The page polls only while something is running.

Scheduled tasks

Entry: /tasks/scheduled. Cron-style recurring actions (for example nightly inbox triage, periodic Dream runs, scheduled Wiki generation) with recent execution results.

Inbox

Entry: /inbox, with an unread badge in the navigation. Aggregates things that need attention (failed tasks, approval requests, system notices) with read / unread state, archiving and category filters.
