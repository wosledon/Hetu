Graph & Wiki

Two ways to turn scattered content into structure: the graph extracts entities and relations, Wiki writes repository material into documents.

Knowledge graph

Extraction

  1. Click “Extract graph” in the note editor (or re-extract existing content).
  2. The LLM pulls entities (name, type) and relations (source, target, type) from the text; results are deduplicated and merged.
  3. Rows land in the graph tables and a background task (GraphExtract) records duration and status.

Entity and relation types

Entity typeMeaning

Wiki generation

Inputs

  • Repository material: README, directory structure, representative source files.
  • Optional semantic search to add related indexed content per module.
  • The model comes from Settings → Default models → Wiki generation.

Stages

StageOutput
Material collectionReads the README and directory tree, picks representative files
Module pagesOne page per module, generated concurrently (module count and concurrency are bounded)
Overview pageProject summary, structure and quick start; titled after the project and sorted first
PersistOne run = one suite (SetId); pages carry a sort order

The whole run is a background task (WikiGenerate) with stage and progress recorded; failures show their reason and can be re-run.

Browsing

  • The Wiki page groups suites: project name, generation time, page count, and an “updated” hint when repository material changed afterwards.
  • Within a suite the overview comes first, then module pages.
  • Generation can be started straight from a project card.
