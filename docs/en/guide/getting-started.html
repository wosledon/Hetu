Getting started

Three paths: install the desktop app, run from source, or use desktop development mode. First-time setup takes about five minutes.

Recommended first run: install → add a provider → add a model → set defaults → write a note and generate an index. If you only want to look around, open the Code page right after installing.

0. What you need

ScenarioRequirements
Desktop (fat)Windows 10/11 x64 or a mainstream Linux distribution; no .NET install required
Desktop (slim)Same, plus the .NET 10 runtime installed on the system
From source.NET SDK 10.0+, Node.js 20+, Git
A modelAn OpenAI-compatible or Anthropic API key; a local inference server also works

1. Install the desktop app

Download from GitHub Releases:

ChannelArtifactNotes
fatHetu_x.y.z_x64-setup.exe / .msiBundles the .NET 10 runtime; larger, works immediately
slimHetu (Slim)_x.y.z_x64-setup.exe / .msiRequires the system .NET 10 runtime; smaller
Linux.AppImage / .debRun chmod +x on the AppImage
fat and slim are independent update channels: a slim install only receives slim updates and will not be replaced by fat.

Closing the main window minimises to the tray by default, and the backend plus background jobs keep running. Use “Quit Hetu” in the tray menu to exit; this behaviour can be changed in Settings → App settings.

2. First-time configuration

StepWhereNotes
Add a providerModels → Add providerChoose OpenAI-compatible or Anthropic; enter the base URL and API key
Add a modelModel list under the providerPurpose is chat, embedding or completion
Set defaultsSettings → Default modelsPer scenario: chat, coding, Wiki, graph, organisation, note AI, query rewrite
Feed knowledgeKnowledge baseAdd a URL or upload a file; in a note, use “Generate index” in the editor toolbar
Try itCode pageTurn on the “Knowledge base” toggle above the input to cite retrieved results
Anthropic has no public embedding endpoint; choose an OpenAI-compatible provider for the embedding purpose. Vector dimensions must match the model (Embedding:Dimensions, default 1536) or writes will fail.

3. Run from source

git clone https://github.com/wosledon/Hetu
cd Hetu

pwsh ./scripts/start.ps1        # Windows: start frontend and backend
./scripts/start.sh              # Linux / macOS

# Or start them separately
dotnet run --project src/Hetu.Api --urls "http://localhost:5000"
cd frontend && npm install && npm run dev   # http://localhost:5174
AddressPurpose
http://localhost:5174Frontend UI
http://localhost:5000/apiBackend API
http://localhost:5000/scalar/v1API reference (Scalar)
http://localhost:5000/api/healthHealth check; the desktop shell uses it to detect readiness

Confirm the backend is up:

curl http://localhost:5000/api/health

4. Desktop development mode

When changing the Rust shell, tray, updater or sidecar integration, desktop development mode starts dotnet, Vite and Tauri together:

pwsh ./scripts/desktop-dev.ps1

If port 5000 already has a backend during development, Tauri reuses it instead of conflicting with your own dotnet run.

5. Where data lives

ModeLocation
Desktop (Windows)%LOCALAPPDATA%\Hetu: hetu.db and WAL, plus logs/
From sourceSet by HETU_DATA_DIR; defaults to hetu.db in the working directory
Backup / migrationQuit the app and copy the whole directory; the database and logs live together

Troubleshooting

SymptomCheck first
Frontend will not openWhether port 5174 is taken; whether Vite exited with an error
API 500 / connection refusedWhether /api/health responds; whether another process owns port 5000
Indexing stallsIndex progress in the knowledge base, embedding model availability and dimension match
Installer says a file is in useQuit Hetu from the tray; a leftover Hetu.Api.exe can lock vec0.dll

More errors and remedies are in the FAQ; for internals start at Architecture.
