Local models

The Foundry Local runtime inside Hetu: browse the model catalog, download, load and unload models, move the model directory, and wire models straight into chat and the knowledge base.

What it is

Local models plug the Foundry Local inference runtime into Hetu: run open-source models on your own GPU/NPU with no API key and no network. It covers the main surface of the foundry command line tool, and chat, Code sessions, knowledge-base chunking and embeddings can all switch to these models.

Entry point: the Local models item in the left navigation (/foundry-local). It is off by default in the dynamic zone — turn it on under Settings → Navigation to keep it pinned.

Runtime status

A status card at the top of the page reflects the local runtime in real time:

FieldMeaning
Run stateWhether the local OpenAI-compatible service is listening; Start service / Stop service map to foundry service start/stop
EndpointSomething like http://127.0.0.1:5272/v1. The port is assigned by the runtime, so it is not fixed
LoadedHow many models are resident in memory (maps to foundry service ps) — these are the ones holding VRAM/RAM
DownloadedHow many models are cached locally (maps to foundry cache list)

Model directory

Models run to several GB, so the location is configurable right on the page: enter an absolute path, save, and restart Hetu.

  • The default is foundry-models inside the Hetu data directory, following the same precedence as SQLite and logs (Hetu:DataDir → HETU_DATA_DIR → the OS local app-data folder)
  • Reset to default returns to that directory in one click
  • Saving takes effect only after you restart Hetu — the local runtime is a process-wide singleton that cannot be rebuilt in place. The page shows a restart prompt
  • Changing the path does not migrate downloaded files: copy the old directory's contents to the new one with File Explorer before restarting, or delete the old cache and download again

Model catalog

The middle of the page is the model catalog, sorted by downloaded-first then name, with publisher, model type, context length and size on each row.

ActionMeaning
DownloadThe first download needs network access to the model source; the progress bar updates live. Files land in the directory above
Load / UnloadMaps to foundry model load/unload. Only a loaded model actually takes VRAM; unloading releases it immediately
DeleteDeletes the local files (maps to foundry cache remove); you will need to download again to use it
Wire into HetuRegisters the model as a chat model under the Foundry Local provider, after which you can pick it in chat and Code sessions

A row of filter dropdowns sits above the catalog, with options and counts generated from the catalog data itself: task, input modality, device (CPU / GPU / NPU), tool-calling support and download state; sorting on the right switches between name, size and context length. The search box filters by alias, display name, publisher and type.

Wiring into Hetu models

Wire into Hetu does two things: creates a foundry provider (no API key; the base URL is the current endpoint) and registers the model as a chat model. After that:

  • Under Settings → Models you can make it the default chat model, or change its purpose, context length and so on
  • Embedding works the same way: register a local embedding model and knowledge-base vector indexing runs entirely locally
  • A provider can also be added by hand: pick Foundry Local (local) as the type and fill in the base URL the runtime reports — that is the path for pointing at a Foundry Local instance on another machine
The port can change when the local service restarts. If a chat request fails to connect, come back here, check the current endpoint and update the provider's base URL.

Platform support

Foundry Local currently supports Windows only (it depends on DirectML / WinML). On Linux and macOS the entry point stays but is greyed out with an explanation; in that case you can still add an OpenAI-compatible provider by hand, pointing at a Foundry Local endpoint on a Windows machine.

Data and API

The management endpoints follow the unified response convention, with short-lived response caching on read-only lists:

MethodPathNotes
GET/api/foundry-local/statusRun state, endpoint, model directory, loaded/downloaded counts
GET/api/foundry-local/models?cachedOnly=falseModel catalog; cachedOnly=true for what is already local
GET/api/foundry-local/models/loadedModels currently resident in memory
POST/api/foundry-local/models/{alias}/downloadDownload; SSE frames {alias, progress, state, error}
POST/api/foundry-local/models/{alias}/load / unloadLoad / unload
POST/api/foundry-local/models/{alias}/register?purpose=chatRegister as a Hetu model; returns the model id
DELETE/api/foundry-local/models/{alias}Delete the local cache
POST/api/foundry-local/service/start / stopStart / stop the local OpenAI-compatible service
PUT/api/foundry-local/model-dirSet the model directory; empty restores the default

Inference itself uses the OpenAI-compatible protocol, dispatched by the existing LLM / Embedding factories on the foundry provider type — no second inference protocol is introduced.
